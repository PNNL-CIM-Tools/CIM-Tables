# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cimtables` implements the `.cimtbl` DSL — a hand-editable tabular text format for CIM power-system models — as parser → profile-reflective validator → binder onto live `cim-graph` objects. It was split out of CIM-Builder (`/home/ande188/CIM-Builder`, package `cimbuilder`), which now depends on this package. **`cimtables` must never import `cimbuilder`**; the dependency is strictly `cimprofiles` → `cim-graph` → `cimtables` → `cimbuilder`.

The design of record is `docs/CIMTBL_DESIGN.md`: the format, the pipeline, and the decisions, as built. Keep it current when behaviour changes, and don't cite it (or anything else) by section number; reference headings by name. The pre-implementation design and its history are in CIM-Builder's git history (`cimbuilder/development/CIMTBL_DESIGN.md`, `GRAPH_WRITE_CONTRACT.md`, `PROFILE_RESOLUTION.md`); don't point code at them.

Git-tracked `.cimtbl` grid models (the target for migrating OpenDSS models) live in the sibling repo `/home/ande188/CIMTBL-Models` (`PNNL-CIM-Tools/CIMTBL-Models`, working branch `feature/1`; `distribution/`, `transmission/`, `tiered_tso_dso/`). It's a plain clone, not a submodule — reference it by path; `tests/fixtures/` stays self-contained.

## Pipeline architecture

```
.cimtbl text ─parser─▶ RawRecord ─validate─▶ <Class>Row dataclass ─bind_row─▶ live cim-graph object in network
```

`cimtables.load(path, network)` in `__init__.py` is the whole pipeline in three lines; it is the ObjectBuilder-free entry point. `cimtables.load_text(text, network)` is the same for a string (an `Import` raises: it needs a file to resolve against). CIM-Builder's `ObjectBuilder.from_table` delegates to the same `bind_row`. `cimtables.load_model(path)` builds the model too: the file's `Profile =`, an in-memory model (`connection=None`) with no container while rows bind (so `network.container` never leaks into `EquipmentContainer`), then the file's one Feeder (→ `FeederModel`), else its one Substation, else None (→ `NodeBreakerModel`) as the container; `load_model(path, model_cls=BusBranchModel)` builds a `BusBranchModel` instead (container: the file's one `GeographicalRegion`, else None). `load` / `load_text` raise `CimtblValidationError` if the file's `Profile =` is not `network.cim`'s module (rows would validate against one profile and bind with another). Both `load` and `load_model` apply the file's `Authority =` / `Model =` through cim-graph's `set_model_scope` before binding, so UUIDs are seeded per model (bus `671` in IEEE13 and IEEE123 differ); `write_xml`'s model header carries the scope and the XML reader restores it. An undeclared half of the scope is left as it is (process-global, like the profile).

- **`grammar.lark` / `parser.py`** — fixed, profile-agnostic Lark grammar: knows only the settings `Profile =` / `Authority =` / `Model =`, `Import <file>.cimtbl`, `Object <Class>: k=v, ...`, `Table <Class>: header, ...` + rows, their additive twins `Update <Class>: ...` / `Update Table <Class>: ...` (`RawRecord.form == 'Update'`), `(unit)` suffixes, `#` comments, blank cell = unset, CSV-style `"..."` cells (`,` `#` `(` `)` literal inside, `""` = one quote; a quoted `""` is the empty string, not unset). Knows **no** CIM class names — never add CIM-specific rules here. `Import` is resolved inline (textual composition), and the settings are consumed before records are built (each at most once per file/Import chain; a conflicting Import raises); `parse_file` returns `(records, Header(profile, authority, model))`; `parse_text` (no filesystem) returns each `Import` in place as an `ImportRecord(path, source_file, source_line)`, never a `RawRecord`. The parser applies none of them — `load` / `load_model` do. Statement keywords are lexed only where their statement shape follows (`Table X:`, `Profile =`, `Import x`), so a row cell like `Object_1` / `Profiles` / `Update` is a value. A row with more cells than the header has columns raises. Syntax errors raise `CimtblParseError` (a `ValueError`) as `<file>:<line>:<col>: ...`, naming the imported file the error is in; a missing Import, an Import cycle, and an Import whose setting conflicts all raise it at the importing file and line (a file imported from two branches is not a cycle). Files are read and written as UTF-8 (`\n` on write).
- **`records.py`** — `RawRecord`: all cells still `str | None`, plus per-column units and source file/line for line-numbered errors. `ImportRecord`: an unresolved `Import`.
- **`validate.py`** — reflects on the active CIM profile module (no LinkML / no curated schema) to build a `<Class>Row` dataclass on demand per (profile, class), coerces cells, wraps unit-bearing fields in `Qty`, and raises `CimtblValidationError` (with closest-attribute suggestions) *before* any graph mutation. Profile comes from `CIMG_CIM_PROFILE`, resolved through cim-graph's `get_cim_profile()` so the module is identical to `network.cim` (comma-spec merged profiles included). FK fields remain unresolved mRID strings at this stage. The row key is reflective: an `IdentifiedObject` row requires `mRID`; a CIM 18 Identity-only class (no `mRID` field, e.g. `PhaseImpedanceData`) takes an optional `identifier` column instead.
- **`synthetic.py`** — the only non-reflective vocabulary: DSL-only columns, exact names only (`node`/`node1`/`node2` → ConnectivityNode, `bus`/`bus1`/`bus2` → TopologicalNode, each fixing the Terminal `sequenceNumber`; `phases`). Never match by prefix: real attributes like `TopologicalNode.busName` exist. A real CIM attribute of the same name wins. There is no `Template` column: a reusable template is a real association (`ACLineSegment.WireConfiguration`, `TransformerTank.TankConfiguration`).
- **`binder.py`** — `bind_row` builds the object from the row key only (`cim_cls(mRID=...)`, so the UUID is seeded from the mRID and a rename keeps it; an Identity-only row's `identifier` seeds the UUID the same way via `obj.uuid(mRID=...)`, and without one the UUID is random). It then classifies every row field purely from the profile into: connectivity column → `connectivity.add_connectivity`; `EquipmentContainer` → `graph_write.resolve` + container override; other reference slot → `graph_write.resolve` + `set_assc` (unresolved mRID raises — references must be declared before use); everything else, `name` included, → `set_attr`. No per-class dispatch table — keep it that way. A `ValueError`/`TypeError` binding a row read from a file is re-raised as `CimtblBindError` (subclasses both, original as `__cause__`) prefixed `<file>:<line>: `; a hand-built row (no `source_file`) raises unchanged.
- **`Update` (additive)** — CIM's formative vs additive definitions (a profile's Concrete vs Description stereotype): `Object`/`Table` define an object, `Update` adds to one defined earlier, possibly in another file, as RDF XML adds properties to an `rdf:about`. The loaders pass `bind_row(..., update=True)`: the mRID must already be bound in that class or a subclass; columns are set as in a formative row (references with their inverse side, pu on the existing ratings); a single-valued field already set raises (an Update never overwrites); connectivity/phase shorthand raises (no second set of Terminals); no `EquipmentContainer` is defaulted, and the object is not re-added. This is how a reference cycle is broken: `Update LinearShuntCompensator: mRID=cap_c1, RegulatingControl=rc_c1` after `RegulatingControl rc_c1` names the compensator's generated `cap_c1_T1`. `document.Table` / `ObjectStatement` take `update=True` to write one.
- **`connectivity.py`** — Terminal synthesis (one per `sequenceNumber`, taken from the column name, not header order; `add_connectivity(node_cols=, bus_cols=)` takes either or both, so `node1` + `bus1` put one Terminal on its ConnectivityNode *and* TopologicalNode, as PSS/E RAW's node-breaker substation data does), auto-vivification of undeclared nodes/buses, and `phases` shorthand. Phases are tokens in conductor order (`CB`, `s1s2N`). Every Terminal gets the canonical PhaseCode (`BC`, `s12N`), and one `<Class>Phase` child is made per token. The class is found by walking the MRO (`Breaker` → `SwitchPhase`, which uses `phaseSide1/2`). A switch whose sides differ takes `phaseSide1=AB, phaseSide2=AC` columns instead of `phases`: paired by position (A→A, B→C), each Terminal gets its side's PhaseCode; on a single-`phase` child class differing sides raise. Every child gets the normative `SinglePhaseKind`. Exception: a delta shunt (`phaseConnection=D`) gets one child per line-to-line branch (`N` ignored), whose `phase` is the from-phase (normative: "to the next logical non-neutral phase", A→B→C→A, s1→s2), plus the branch PhaseCode in the `phases` extension where the class has it (cim18v17 `EnergyConsumerPhase` etc.): CA → phase=C, phases=AC. Generated objects are keyed off the owner's mRID: Terminals `<mRID>_T<n>`, phase children `<mRID>_<phase>` (delta branches `<mRID>_<BC>`); auto-vivified nodes/buses take the cell value as mRID. A `TransformerEnd` row's `node`/`bus` puts its Terminal on the end's transformer, the end's one ConductingEquipment reference found by type hint (`PowerTransformerEnd.PowerTransformer`, `AutoTransformerEnd.AutoTransformer`; `sequenceNumber` = `endNumber`); `bind_row` resolves FKs before connectivity for this. An `AutoTransformerEnd`'s real `phase` (a PhaseCode) is copied to its Terminal's `phases`, and a `phases` column on it raises. A `VoltageRegulator` has no `<Class>Phase` child, so `phases` on it raises. The shorthand only applies where the class has no real `phases` attribute (`Terminal.phases`, `EnergyConsumerPhase.phases` are set literally).
- **`graph_write.py`** — the **only** module that mutates cim-graph objects or the network (`set_attr`, `set_assc`, `add_to_graph`, `resolve`). `resolve(network, cls, mRID)` is cim-graph's `find_by_mRID` plus an `isinstance` check: any subclass of an abstract slot class matches, and an mRID belonging to another class raises. Other code must route through it rather than calling `setattr` / `network.add_to_graph` directly. `set_attr`/`set_assc` take a `part` profile-module checked by class *name* only; passing `network.cim` is the documented no-op check used at reflective call sites.
- **mRID index** — lives in cim-graph (`GraphModel.find_by_mRID` / `mrid_index` / `list_identities`), kept by `GraphModel.add_to_graph`. mRIDs are unique **within the model, not per class** (CIM 18); reusing one in any class raises. `name` is optional, non-unique data. Identity-only objects have no mRID and are not indexed (nothing references them).
- **`units.py`** — `Qty(value, unit)` carrier from the `(unit)` header suffix; converted to `CIMUnit` in `set_attr`.
- **`get_qty`** — `graph_write.get_qty(obj, attr, unit, base=None, system_base=None)` is `set_attr`'s read-side mirror for exporters: the value in `unit`, or None if unset; `pu`/`percent` on ohm/siemens attributes invert through the same `impedance.z_base` (`base='system'` = `(pu system)`), so one rule decides the base both ways. Non-fields, associations, non-CIMUnit attributes and a base on a non-relative unit raise.
- **PerCent** — a PerCent-typed attribute (`percentImpedance`, `pfixedPct`, ...) holds the percent number: a bare number, a unitless column or `(percent)` / `Qty(5, 'percent')` all store `PerCent(5.0)` (CIM XML `5.0`; pint alone would store 0.05). Any other unit on it raises, `pu` included; `get_qty(..., 'percent')` returns the stored number.
- **Speed** — per-class reflection is cached (`graph_write.type_hints`, `graph_write._si_unit_name`, `validate._real_fields`; classes never change once imported, so never mutate the results), and `set_assc` skips the reverse-list dedup scan when the forward side is singular and did not already point at the target, so binding stays linear (CIMHub G7: ~3,300-3,900 rows/s, from 400).
- **Relative impedances** — a `percent`/`pu` Qty on an ohm-typed attribute is multiplied by `z_base = U²/S` in `set_attr` (siemens-typed: divided by it, one base for both); `set_attr` computes it itself (`impedance.z_base(obj, system_base)`) from the object, so the caller passes only `system_base=network.base_power` (the system base power, used only on the system-base path) and must set the ratings, `BaseVoltage` and `From*` references first; `bind_row` writes relative Qtys after FKs for this. The base is chosen by class shape, never by which values are set: the row's own object if its class is rated (`PowerTransformerEnd`), else the target of one of its single-valued `From*` references (`TransformerMeshImpedance.FromWinding`), and a rated class with an unset rating raises. On a class with `baseU`/`baseS` (`TransformerWinding`, filled from the nameplate: ratedU/ratedS = nameplate LL voltage and kVA, baseU = coil voltage (phase-to-neutral for wye, LL for delta), baseS = per-coil kVA: ratedS for a 1φ primary, 2·ratedS for a triplex half, ratedS/3 for a 3φ coil; so `z_base` needs no phase count) those are required; otherwise (`PowerTransformerEnd`) `ratedU`/`ratedS`. An unrated class (`ACLineSegment`, `EnergySource`) uses the system base: its own `BaseVoltage` and the system base power. A bound `Object BasePower: basePower (MVA)=...` sets `network.base_power` in `graph_write.add_to_graph` (one without `basePower`, or a second that disagrees, raises). `bind_row` passes `system_base` only once a `BasePower` is bound (else `None`, so a system-base row raises "a BasePower declared before this row"): a `.cimtbl` model is a function of its text alone, never of cim-graph's `CIMG_SYSTEM_MVA_BASE` / 100 MVA default, and a late `BasePower` can't leave earlier rows on another base. Builders calling `set_attr(..., system_base=network.base_power)` directly are unaffected. cim-graph's `set_default_bases` likewise takes a loaded graph's `BasePower` (CIM XML read, `load_model`'s `FeederModel`). A `(pu system)` / `(percent system)` header suffix (`Qty.base == 'system'`) puts that column on the system base even on a rated class, for source data already on SBASE (PSS/E transformer impedances); `system` is the only base word, and only on `pu`/`percent`. Rationale and open IEC WG questions: `.development/PERCENT_IMPEDANCE_BASE.md`.
- **Scalar typing** — `set_attr` enforces the field's declared type like cim-graph's `create_value`: a bool field takes only a `bool` (never the str `'false'`), a bool is never a number, a number on a CIMUnit field is wrapped as SI base, a CIMUnit is converted into the field's own (per-profile) CIMUnit class; mismatches raise `TypeError`. Text parsing is `validate._coerce`'s job (bool cells: `true/false/1/0` only).
- **`document.py`** — the parser's inverse: a `Document` (`Table` / `ObjectStatement` / `Import` statements of cell *text*, `None` = blank, `''` = quoted empty, optional comments on documents, tables and rows) → `format_document` → deterministic text (4-space rows, cells padded after the comma to the column width, blank line between statements). It quotes a cell iff it holds `,()#"`, has edge whitespace, is `''`, or starts like a statement; a newline raises. `write_documents(DocumentSet(master, parts), dir)` writes `<name>.cimtbl` for all (names are stems: one ending in `.cimtbl` raises) and returns the master's path, writing nothing if an Import is unknown, a part is never imported, or `dir` holds a stale `.cimtbl`. Typed value → text is the caller's job (CIMHub's importers).
- **`diff.py`** — `diff_models(expected, actual, rel_tol=1e-9)`: object-by-object model comparison (builder-built vs `.cimtbl` golden, CIM-Builder parity tests). Matches by (class, mRID), else `identifier` (Identity-only), never by UUID, so two Authority/Model scopes still compare; CIMUnits in SI within `rel_tol`, other scalars exactly, associations by target mRID (lists as sorted sets); `serialize=False` reverse sides are skipped. Messages: `Class mRID.attr: expected X, got Y`, `Class mRID: missing` / `extra`.
- **Writer** — a cimgraph → `.cimtbl` writer is not built yet (planned design in `docs/CIMTBL_DESIGN.md`); `document.py` is what it would emit through.

## Format conventions worth knowing

- References are by `mRID`. Prefixes keep mRIDs unique across classes (`ld_671` vs bus `671`); the convention is the translator's (CIMTBL-Models' `cimtbl-translate` skill), not enforced beyond uniqueness. `bind_row` resolves references immediately, so declare targets first (second-pass resolution for forward references is an open question in the design doc). Where the profile serializes only one side of an association (e.g. cim18v17 `TransformerWinding.FromTransformerLug` is `serialize=False`), write it from the other side.
- The same class may appear with different header shapes (e.g. `ACLineSegment` by `bus1/bus2` + `r (pu)` vs `node1/node2` + `phases` + `PerLengthImpedance`); presence/absence of fields is the dispatch signal — rows carry no shape flag.
- Matrix impedance is literal `PhaseImpedanceData` rows only; compact `rmatrix`/`xmatrix` sugar is deliberately not supported.
- Source names are kept verbatim, never sanitized: a value with `,` `#` `(` `)` or edge whitespace is quoted (`"#2_ACSR_6/1"`, `"DEFAULT (DC)"`). The UUID is seeded from the mRID verbatim (CIM-Profiles' `seeded_uuid`; only an rdf:about/rdf:ID is normalized, so `lc_#2acsr` and `lc_#2arv` stay distinct), so renaming would change it; CIM XML takes any mRID string.
- `Object` is for singletons, `Table` for many instances (even ragged ones).

## Tests

Tests target `cim18v17` only (cimhub_2026 and gmdm are out of scope). They set `os.environ['CIMG_CIM_PROFILE'] = 'cim18v17'` at module import, build a `BusBranchModel` over an `XMLFile` connection, and parse real `.cimtbl` text rather than hand-built records. Beware: `load_model` writes a file's `Profile =` into `os.environ`, and `load` / `load_model` set the model scope, both process-global (see `tests/test_load_model.py`'s `model_scope` fixture). Fixtures (`ieee13.cimtbl`, `ieee14.cimtbl`, `wire_infos.cimtbl`) are in `tests/fixtures/`.

`tests/test_bind_cim18v17.py` uses a `FeederModel` and sets the profile per test via `monkeypatch.setenv` + `get_cim_profile.cache_clear()`, including a comma-spec merged profile (`cim18v17.connectivity_unbalanced,cim18v17.electrical_unbalanced`) bound end to end.
